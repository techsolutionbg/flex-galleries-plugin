# Flex Galleries

Самостоятелен плъгин за Flex CMS за създаване и вграждане на галерии от медийната библиотека. Поддържа решетка, masonry, carousel слайдер и общия lightbox на платформата.

Версия: **0.2.0** · ID: `flex/galleries` · Минимална версия на Flex CMS: **0.1.62**.

GitHub репозитори: `techsolutionbg/flex-galleries-plugin`.

## Изисквания и инсталиране

Необходима е инсталирана Flex CMS с PHP 8.3+, базата данни и медийната библиотека на платформата. Използват се Extension API V1, административният React интерфейс и общите ресурси `/assets/flex-lightbox.js` и `/assets/flex-lightbox.css`. Не се изисква друг Flex плъгин, собствено копие на React или компилация с npm.

PHP разширението `intl` е необходимо за автоматичното генериране на идентификатор от името чрез `transliterator_transliterate()`. Използват се също DOM и mbstring. Стандартният development PHP образ включва intl.

Поставете пакета в `plugins/flex/galleries/`, с `plugin.json` директно в тази папка. От корена на Flex CMS:

```sh
php bin/flex plugin:install flex/galleries
php bin/flex plugin:activate flex/galleries
```

При Docker добавете префикс `docker compose exec app`. Инсталирането и активирането създават липсващите таблици `flex_galleries` и `flex_gallery_items`, без да пресъздават съществуващите.

## Какво добавя в платформата

- Административна страница **Галерии** в групата за съдържание.
- Създаване, редактиране, търсене, филтриране по статус и кошче с възстановяване.
- Множествен избор на изображения от медийната библиотека.
- Подреждане чрез влачене и бутони за преместване.
- Локални текстови полета за изображенията във всяка галерия.
- Избор на галерия и дизайн през **Добави: Галерии** в редактора на страница.
- Публично рендериране чрез филтъра `public.content`.

## Създаване и вграждане

1. Отворете **Галерии** и създайте галерия.
2. Въведете име и по желание идентификатор. Празният идентификатор се генерира от името и при съвпадение получава цифров суфикс. Ръчният идентификатор трябва да е уникален и да съдържа малки латински букви, цифри и тирета.
3. Изберете изображения, подредете ги и настройте дизайна и текстовете.
4. Изберете статус **Активно** и запазете.
5. В страница използвайте **Добави: Галерии** или поставете препратка:

```text
[gallery id="1"]
[gallery id="1" design="grid"]
[gallery id="1" design="masonry"]
[gallery id="1" design="slider"]
```

Числото е ID на галерията, а не нейният текстов идентификатор. Без `design` се използва основният дизайн. Дизайнът за конкретно поставяне не променя основния дизайн на галерията.

Една страница може да съдържа множество галерии, включително повторения с различни дизайни. Препратките се съхраняват като текст; HTML се генерира при публично показване, без презаписване на съдържанието. Промените в галерията се отразяват на всички нейни поставяния.

Използвайте показания синтаксис с двойни кавички и `id` преди `design`. Препратки в HTML атрибути, `script`, `style`, `pre` и `code` не се обработват.

## Дизайни и настройки

| Настройка | Стойности |
| --- | --- |
| Дизайн | `grid`, `masonry`, `slider` |
| Колони | 1–6 |
| Разстояние | 0–48 px |
| Заобляне | 0–32 px |
| Пропорции | оригинални, квадратни, хоризонтални |
| Ширина | в секцията или по ширината на страницата |
| Запълване | `contain`, `cover`, `scale-down` |
| Височина | `frame`, `auto`, `screen`, `custom` |
| Височина на слайдера | 200–1600 px, при персонализирана височина |
| Надписи и описания | включени/изключени |
| Lightbox | включен/изключен |
| Увеличение в lightbox | включено/изключено; максимум 2–5 |

Всеки дизайн има отделни настройки за колони, пропорции, разстояние, запълване и височина. Новата галерия в администрацията започва като чернова с решетка, 3 колони, 16 px разстояние, 8 px заобляне, оригинални пропорции, ширина в секцията, `cover`, автоматична височина и включени надписи, lightbox и увеличение до 3.

Слайдерът има предишно/следващо изображение, брояч и директен избор на изображение. Поддържа влачене/плъзгане и клавишите ArrowLeft, ArrowRight, Home и End. Навигацията спира при първото и последното изображение. Плавното превъртане се съобразява с предпочитанието за намалено движение.

## Изображения и текстове

До **200 изображения** в галерия, без повторения на media ID. Новите елементи трябва да са налични медии с MIME тип `image/*`.

| Поле | Максимум символи | Поведение |
| --- | ---: | --- |
| `alt` | 500 | Алтернативен текст; при празна стойност публично се използва alt от библиотеката |
| `title` | 500 | HTML `title` атрибут на обвивката на изображението |
| `caption` | 1000 | Надпис при включено показване на надписи |
| `description` | 3000 | Допълнителен текст под надписа |
| `link` | 2000 | Индивидуална връзка вместо lightbox |

Текстовете от библиотеката се копират при добавяне и се редактират локално за галерията. Промените не редактират оригиналната медия или друга галерия. Връзките приемат локален адрес, започващ с `/`, или HTTP/HTTPS URL. Протоколно относителни адреси (`//...`), JavaScript URL, контролни символи и обратни наклонени черти се отхвърлят.

Публичните текстове се екранират. Изображенията използват оригиналния медиен URL, `loading="lazy"`, `decoding="async"` и наличните размери. Lightbox включва изображенията без индивидуална връзка.

## Статуси и запазване на данните

Само активни галерии извън кошчето се показват публично. Чернови, неактивни, липсващи и празни галерии генерират празно съдържание вместо препратката.

Изтрити от библиотеката медии се пропускат публично и се обозначават в редактора. Съществуващи недостъпни изображения могат да останат до премахване или замяна. Галериите не блокират изтриването на медии.

Галерия в кошчето може да се възстанови. Окончателно изтриване е позволено след преместване в кошчето и премахва галерията и нейните елементи, без оригиналните файлове.

Деактивирането не изтрива таблиците и спира регистрацията на публичния филтър, така че препратките остават текст. Плъгинът няма собствена процедура за премахване на таблиците при деинсталиране. Архивирайте таблиците заедно с базата и медийните файлове на платформата.

## Интеграция и административен API

Манифестът декларира `admin.ui`, `routes.admin` и `frontend.assets`. ES модулът получава React, компоненти, заявки и известия от платформата чрез `createPage(host)` и `createEmbedPicker(host)`.

Маршрутите са спрямо `/admin/plugins/flex/galleries`:

| Метод и път | Действие |
| --- | --- |
| `GET /galleries` | Списък; `view=active` е всички галерии извън кошчето, `view=trash` е кошчето |
| `POST /galleries` | Създаване |
| `GET /galleries/{id}` | Четене |
| `PUT /galleries/{id}` | Обновяване |
| `DELETE /galleries/{id}` | Преместване в кошчето |
| `POST /galleries/{id}/restore` | Възстановяване |
| `DELETE /galleries/{id}/force` | Окончателно изтриване |

Ядрото прилага authentication, superadmin и CSRF middleware. Обновяването и действията изискват актуално поле `version`; промяна от друг таб връща HTTP 409. Валидационните грешки връщат 422, липсващите галерии — 404, успешно създаване — 201. JSON отговорите използват `Cache-Control: no-store`.

Няма отделен публичен API за галерии. Renderer-ът обработва съдържанието и добавя ресурсите, когато има показана галерия. Публичният JavaScript поддържа събитията `flex:page-before-change` и `flex:page-ready`.


## Проверки при разработка

Изпълняват се от корена на Flex CMS с инсталирани Composer зависимости:

```sh
node --test plugins/flex/galleries/tests/admin.test.cjs
docker compose exec -T app vendor/bin/phpunit plugins/flex/galleries/tests/GalleryTest.php
```

PHP тестовете използват SQLite в паметта и изискват PDO SQLite и intl. Проверяват CRUD, независими настройки, локални текстове, API, конфликтни версии, валидация, рендериране, екраниране, кошче и интеграция с тема. JavaScript тестовете проверяват редактора, подреждането, настройките и избора за вграждане.

Допълнителната локална проверка изисква `APP_ENV=local`, активен плъгин, активна тема, създадени таблици и поне едно изображение. Записите за галерията се връщат назад с транзакция:

```sh
docker compose exec -T app php plugins/flex/galleries/tests/dev-smoke.php
```

При подготовката на това README преминаха **6 JavaScript теста** и **8 PHP теста с 62 assertions**. Допълнителната проверка `dev-smoke.php` не е изпълнявана.

## Граници на пакета

Плъгинът използва класове и услуги на Flex CMS и не е самостоятелно PHP приложение. Показването зависи от тема, използваща обработеното публично съдържание, и от общите lightbox ресурси. Няма автоматично възпроизвеждане на слайдера, видео галерии или автоматична оптимизация на оригиналните изображения.
